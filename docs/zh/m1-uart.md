# M1 UART 与能力查询

[English](https://phicomm-io.github.io/iotcloud-community-protocols/en/m1-uart/)

Wi-Fi MCU 与传感器 MCU 通过 SERCOM3 UART（115200、8N1）通信。普通请求固定 12 字节，应答/事件固定 20 字节，起始 `23`、结束 `21`；没有独立校验字节，多字节数值为大端。OTA 数据块使用单独的可变长格式，不可交给普通帧解析器。

[按键重置 `0x72`](m1-display.md#m1-reset-v1) 使用独立的 20 字节传感器请求 / 12 字节 Wi-Fi ACK，需在双方固件中配套实现。

## 版本和扩展帧

普通 `0x11` 查询传感器 MCU 版本，应答 `f2` 为长度、`f3` 起为原始字符串，最多 16 字节。联网模块自己的固件版本另列。原厂 `11.x` 建议优先使用开源 MCU 固件；原厂 `17.1.2.3` / `17.x` 待取得相应镜像并完成兼容性分析后再支持。未知版本显示未知，不推断功能。

开源扩展请求：

```text
23 70 OP SEQ A0 A1 A2 A3 A4 A5 A6 21
```

应答：

```text
23 70 OP SEQ STATUS D0 D1 D2 D3 D4 D5 D6 D7 D8 D9 D10 D11 D12 D13 21
```

`SEQ` 为 0..255 的请求匹配号；预留参数和未使用应答字节清零。接收端同时分派普通采样、时间和事件，不将下一帧直接视为当前请求的应答。

| STATUS | 含义 |
| --- | --- |
| 0 | 已接受 / 查询成功 |
| 1 | 参数错误 |
| 2 | OTA 接收中忙 |
| 3 | 不支持 |
| 4 | 外设配置失败 |
| 5 | 传感器缓存代数改变，重新读取 |

成功应答只代表运行时接受请求；显示写入由后续轮询执行。重发相同 `SEQ` 会重新执行。复位提交阶段不再接受新命令。

## OP `00` 能力

参数全零。D0 从应答绝对偏移 5 开始，注意不要混用 D 偏移与帧偏移。

| D 偏移 / 帧偏移 | 定义 |
| --- | --- |
| D0 / f5 | 扩展协议版本，当前 2 |
| D1–2 / f6–7 | OP `00`–`0f` 位图，当前 `ffff` |
| D3–4 / f8–9 | 专家覆盖最长租期，10000 ms |
| D5 / f10 | 硬件 PWM 回调存在 |
| D6–8 / f11–13 | 原始传感器帧 schema、种类数、最大读取块 |
| D9 / f14 | 按钮事件 schema，1 支持下文事件 |
| D10 / f15 | 按钮种类位图，bit0..3 对应种类 1..4，当前 `0f` |
| D11 / f16 | 通用 Wi-Fi 显示 schema，1 支持 OP `11`–`13` |
| D12 / f17 | 可选传感器蜂鸣器 schema；1 支持 OP `14`，0 表示未提供 |
| D13 / f18 | `m1-uart-v3` 双路显示 schema；2 支持 OP `15`–`17`，0 未提供；旧 v2 合同固定为0 |

原厂 MCU 不支持 `0x70`。新增能力通过 D9..D13 协商，不改变 D1–2 旧位图含义或 D0=2。查询不到能力时停用对应扩展。新增 schema 属于开发实现，不能仅凭 Wi-Fi 固件版本认定传感器 MCU 已升级。

合同 revision 与帧内协议号分别管理：旧 `m1-uart-v2` 的机器定义 [v1 artifact](contracts/m1-uart-v1.json) 和[原向量](contracts/vectors/m1-uart-v1.json) 保持原样，仍要求 D13=0。新增 [v3 artifact](contracts/m1-uart-v3.json) / [v3 向量](contracts/vectors/m1-uart-v3.json) 单独声明 D13=2 与双路操作，支持读出0表示旧能力。消费者须显式选择新合同并更新 pin，不能把非零 D13 宣称为符合旧固定零合同。旧 Wi-Fi 忽略该新增能力时仍使用 scalar 接口。

## 操作码分组

| 类别 | OP | 用途 |
| --- | --- | --- |
| 正式功能 | `09`、`0b`、`0e`、`0f`、`11`、`12`、`14`–`16` | 阈值、音色/音乐、scalar/双路显示写入与选择、可选传感器蜂鸣器 |
| 兼容入口 | `0a`、`0c`、`0d` | 既有 CO₂ 显示配置、读数与状态；v1 新实现改用通用显示源 |
| 只读诊断 | `00`、`06`、`08`、`10`、`13`、`17` | 能力、健康、显示缓存、原始传感器帧、scalar/双路状态 |
| 专家工具 | `01`–`05`、`07` | PWM、屏幕/数值/段覆盖、退出、PM 模式 |

既有操作码继续保留。完整既有命令与音乐/升级细节见 [MCU 实现文档](https://github.com/phicomm-io/phicomm_m1_mcu_atsamd20/tree/main/docs)。跨仓库新显示和按钮接口在 [下一页](m1-display.md) 集中维护。

## OP `14`：可选传感器蜂鸣器

此处 OP `14` 是十六进制 `0x14`，即十进制 20。必须先确认 OP `00` D12 等于 1。它只控制超阈值传感器提醒，不屏蔽唤醒闹钟、音乐或显式蜂鸣器命令。

| 字节 | 请求 |
| --- | --- |
| A0 | 0：只读；1：写入整个启用位图 |
| A1 | 写入位图：bit0 甲醛、bit1 PM2.5、bit2 既有 CO₂；bit3..7 必须为零。只读时必须为零 |
| A2..A6 | 必须为零 |

成功应答中 STATUS 在 f4；D0 为 schema 1，D1 为 MCU 当前实际启用位图（0..7），D2 为最近一次运行时轮询的 `alarm_latched`（0/1），D3..D13 为零。参数不合法返回 STATUS 1，OTA 忙返回 STATUS 2。`alarm_latched` 表示已启用且健康传感器的超红阈值条件；它不是声音检测，不能证明蜂鸣器此刻正在发声。

MCU 的位图只保存在 RAM，冷启动为 0，即默认全部关闭。Wi-Fi 端持久保存甲醛和 PM2.5 两个期望开关（0..3），读取能力后发送写请求，再用独立只读请求核对位图；写应答不能作为读回确认。读回须与当前配置修订号对应并保持新鲜，成功后每 5 秒继续读取，15 秒无新鲜读回即视为未知。旧 MCU 可以保存期望设置，但不得发送未声明的 OP `14`，也不得宣称已关闭实际蜂鸣器。[`alarm.get/set`](device-http.md#m1) 分开报告期望和实际状态。

## PM2.5 稳定读数与原始诊断

开发实现保持每 3 秒采样，先取最近三次有效读数的中值，再用 Q8 EMA 生成普通显示/遥测读数。首次有效样本用于初始化：上升差值至少 20 µg/m³ 时采用 75% 新值；较小上升采用 50%；下降采用 25%。这会抑制单次突变，并使连续真实上升较快反映到显示。滤波状态占 12 字节，不改变 UART 帧长度、旧能力位图或原始传感器字节。

错误帧不向滤波器注入零。连续三次错误，或距上次健康样本超过 6000 ms 时，健康状态失效并重新预热；无效状态不能对外作为有效的零浓度。OP `10` 原始传感器诊断保留传感器收到的原始帧，包括错误帧与未采纳突变；显示平滑值不能替代诊断原文。

诊断标志仍为 `PRESENT=0x01`、`CHECKED=0x02`、`ERROR=0x04`、`WARMING=0x08`、`FILTERED=0x10`。只有原始值与中值差至少 20，且差值超过中值的 50% 时，才置 `FILTERED`，表示大幅原始突变尚未被中值确认。普通 EMA 平滑不置此位。原始值、平滑读数、健康/预热与该标志是不同信息，不得互相推断。

实现入口：`mcu/src/{debug,runtime,pm_filter}.c`、`mcu/tests/{test_core,test_runtime,test_pm_filter}.c`、`firmware/M1/mcu.c`。仓库别名和提交固定方式见 [机器契约](contracts.md)。这些是源码与主机测试边界，不表示新 v1 已发布或完成真机验收。
