# M1 显示源与按钮事件

[English](https://phicomm-io.github.io/iotcloud-community-protocols/en/m1-display/)

格式与独立灯段合同 `m1-display-v3` 使用增量 `m1-uart-v4`，保留双路 schema 2 和 scalar schema 1 的原义。以下是未正式发布的开发接口。

## Wi-Fi profile4 与 UART 版本

RC.1改用[通用字段profile4](device-http.md#m1-generic-profile4)和[sensor-values-v2](mqtt.md#sensor-values-v2)，MQTT来源只按设备身份+field_id/type/unit绑定，不按TC1/A1等机型适配。旧RC profile3/schema1 feed已弃用，不保证兼容。下方玻璃格式、raw API与UART schema3仍使用既有定义；profile4没有增加UART操作码。RC.1尚未公开发布。

## M1 display v3

slot0 是甲醛区域，slot1 是 PM2.5 区域。甲醛区域的小数点固定在第一位之后，PM 区域仅支持整数。本地/MQTT 配置的 `unit` 表示来源数值的物理单位；它不会在玻璃上生成 ppm、W 或 % 字形。`display.show_label` 控制原有“甲醛”/“PM2.5”字样，`display.show_unit` 独立控制原有 mg/m³ / µg/m³ 单位段。两者均为必填布尔值；自定义/外部数据的初始值为 false。

以下模式转换本地/MQTT 物理输入。直接 API 则明确提供数字寄存器、三个标志和全部九段色灯。

| `display.mode` | 甲醛区域显示规则 | 示例 / 上限 |
| --- | --- | --- |
| `integer` | 四舍五入为整数 | 123.5 → `124`；最大 `999`；PM 仅允许此模式 |
| `auto_kilo` | 原值小于 1000 时显示整数，否则除以 1000 显示 x.xx | 1234 → `1.23`；缩放后最大 `9.99` |
| `decimal_2` | 四舍五入至百分位，固定 x.xx | 1.2351 → `1.24`；最大 `9.99` |
| `decimal_1` | 四舍五入至十分位，末位固定为 0 | 1.251 → `1.30`；最大 `9.90` |
| `milli` | 原值除以 1000，四舍五入至百分位 | 1234 → `1.23`；最大 `9.99` |

物理输入与计算沿用 float32，正数中点向上取整。正数显示溢出仍有效，饱和到该模式上限；负数、非有限数或不符合 metric 范围的数据无效，恢复该区域原读数。阈值始终比较转换前的物理输入。两区域各自到期、全局原始/用户选择、双击整体切换及闹钟优先级保持原义。

每区域具有左、中、右三个位置，每位置的红、绿、黄段可以分别开关，共 9 段；同一位置允许多色同时开启。固定颜色使用下列完整对象：

```json
{"mode":"fixed","lamps":[{"red":true,"green":false,"yellow":false},{"red":false,"green":true,"yellow":false},{"red":true,"green":false,"yellow":true}]}
```

数组顺序为物理左/中/右，每项必须含且仅含三个布尔值。阈值模式仍为 `{"mode":"thresholds","low":1000,"high":2000}`：低于 low 三位置全绿，[low, high) 全黄，达到 high 全红；必须 low<high。直接 API 必须提供完整 `lamps` 数组，原样设置各段，不使用配置阈值。这些显示灯段不改变传感器采样或报警。

### UART 格式与灯位

OP `00` D13 / f18 继续为 2，不增加或重解释旧能力字节。先确认该能力，再以只读 OP26 / `0x1a` 查询 schema3。旧 MCU 返回不支持/无效操作或查询失败时，限制重试次数，不发送 OP24/25，并报告 `requires_mcu_upgrade`。

| 十进制 OP / 十六进制 | 参数 | 作用 |
| --- | --- | --- |
| 24 / `18` write | A0–1 number BE16 0..999；A2 format；A3–4 lamps BE16 0..511；A5 TTL 0..60；A6 slot 0..1 | 只更新所选独立格式缓存；TTL0 清除该缓存 |
| 25 / `19` select | A0=0 原始 / 1 用户；A1..6=0 | 显式激活 formatted profile，包括选择原始时 |
| 26 / `1a` query | A0=slot；A1..6=0 | 只读该路缓存、所保存的选择及 profile 是否激活 |

format bit0=甲醛第一位后的小数点，bit1=原标签，bit2=原单位，bit3..7=0。PM 的 bit0 必须为零。新格式缓存独立于旧 scalar/dual 缓存；写入和查询不切 profile，旧十进制 OP10/18/22（十六进制 `0a`/`12`/`16`）分别显式取回旧 CO₂/scalar/dual 显示所有权。专家覆盖、OTA 与复位优先级不变。

lamps bit0..2 为红色左/中/右，bit3..5 为绿色左/中/右，bit6..8 为黄色左/中/右。全红=`0x007`、全绿=`0x038`、全黄=`0x1c0`。上例混合灯段为 `0x115`。对应 LCD RAM 颜色字节为红 `0x0c`、绿 `0x13`、黄 `0x12`；甲醛位置掩码为 `0x10/0x20/0x40`，PM 为 `0x80/0x01/0x04`。只清除并替换所选区域的位，保留三个颜色字节中的其他所有位。

例如写甲醛 `1.23`、混合灯段、20 秒租期，然后选择用户来源并独立查询：

```text
23 70 18 01 00 7b 01 01 15 14 00 21
23 70 19 02 01 00 00 00 00 00 00 21
23 70 1a 03 00 00 00 00 00 00 00 21
```

写入/选择成功的数据字节全零。OP26 成功应答使用绝对偏移：f5=schema3，f6=缓存选择，f7=effective，f8=slot，f9–10=number，f11=format，f12–13=lamps，f14=剩余 TTL 向上取整（0..60），f15=formatted profile 激活，f16..18=0。effective 需要激活、用户选择且 TTL>0。

OP26 单独不能证明选择已经下发。Wi-Fi 必须先收到属于当前配置 generation 的匹配 OP25 ACK，再独立查询两路，核对 f15=1、选择、编码数值、格式、灯掩码和新鲜 TTL；旧 v2 缓存应答不能确认 formatted。HTTP/MQTT 配置、运行时和兼容视图见 [display_profile API](device-http.md#m1-display_profile-api)。机器定义与数值/帧向量见 [合同与样例](contracts.md)。

## 兼容的双路 schema 2

甲醛位 `slot=0` 与 PM2.5 位 `slot=1` 各有独立数值、格式、颜色和租期。一个全局选择器控制两路原始读数 / 两路用户显示，双击一次整体切换。source=`none`、缺失、过期、离线或超出表示范围时，仅该位置恢复原始读数；另一路不受影响。到期不改变全局 desired 选择，新鲜数据可恢复该路用户显示。

Wi-Fi MCU 负责来源、物理单位、缩放和颜色，传感器 MCU 只渲染编码。用户数值不得替代真实采样、告警输入或物理传感器发布。API 配置见 [双路显示 API](device-http.md#m1-dual-display-api)，跨设备数据见 [typed sensor feed](mqtt.md#sensor-values-v1)。

### 能力与操作

只有 OP `00` 的 D13 / f18=`2` 才允许新写入；D11 / f16 仍为旧 scalar schema `1`，D12 / f17 仍为独立蜂鸣器 schema。外层扩展协议 D0 仍为 `2`。新 Wi-Fi 还须以只读 OP `17` 核对 schema 2；未声明、未知值或查询失败时保持原始显示，不尝试新写入。

以下 OP 使用十六进制（`15`/`16`/`17` 即十进制 21/22/23），沿用 [扩展帧](m1-uart.md)。

| OP | 参数 | 作用 |
| --- | --- | --- |
| `15` dual.write | A0–1 BE16 number 0..999；A2 format；A3 color 0..3；A4 TTL 0..60 秒；A5 slot 0..1；A6=0 | 只更新该路缓存；0 秒立即清除，不选择 profile 或来源 |
| `16` dual.select | A0=0 原始 / 1 用户；A1..6=0 | 选择 dual profile，并用一个操作整体切换两路 |
| `17` dual.query | A0=slot 0..1；A1..6=0 | 只读该路缓存与全局选择，不切 profile、不续租 |

format、color 编码沿用下文 scalar 定义。写入 / 选择成功应答数据为零；失败遵循既有状态码，不得部分修改。OP `17` 返回 D0=2、D1=dual 全局选择、D2=当前 profile 为 dual 且选择用户且该路缓存有效、D3=slot、D4–5=number、D6=format、D7=color、D8=剩余 TTL 向上取整、D9..13=0。即使 D2=1，也不证明 LCD 硬件写入或专家覆盖下的最终可见内容。

两路缓存、到期时间和全局选择均为 MCU RAM；冷启动无有效租期、选择原始。专家屏幕覆盖优先。每路写入是独立刷新，只有选择器整体切换是单次操作；不承诺两次独立数值写入原子提交。确认必须在写入后独立查询两路，并匹配当前配置、选择、数值、格式、颜色与新鲜租期；写 ACK 不构成确认。

例如独立写两个位置，再整体选择用户来源：

```text
23 70 15 01 00 7b 01 03 14 00 00 21
23 70 15 02 01 c8 02 02 0a 01 00 21
23 70 16 03 01 00 00 00 00 00 00 21
23 70 17 04 00 00 00 00 00 00 00 21
23 70 17 05 01 00 00 00 00 00 00 21
```

### 数字、单位与颜色

每路只有三位非负数字：format 0 显示 `123`，1 显示 `1.23`，2 显示 `12.3`；API decimals 0/1/2 分别映射 format 0/2/1。没有 generic 负号或任意文本。Wi-Fi 编码 `floor(value / scale * 10^decimals + 0.5)`；数值必须有限、非负、符合 metric 范围且结果 0..999，否则该路恢复原始读数，不钳位、不绕回、不伪零。

逻辑 unit 与玻璃单位段分开。玻璃没有这两路可选择的 W、kW、℃、%、CO₂ 或 ppm 字形；显示 TC1 功率时必须隐藏原气体/单位段，并在 UI 说明逻辑单位和倍率。仅 slot0+formaldehyde+`mg/m³`+scale1，或 slot1+pm25+`µg/m³`+scale1 可保留原 legend；scale1000 即使原 metric 也必须隐藏，避免错标。`1230 W / scale1000 / decimals2` 显示约 `1.23`，不表示玻璃上出现了 kW。

颜色为 off/red/green/yellow；thresholds 模式必须 low<high，按缩放前物理值比较：`<low` 绿、`>=low && <high` 黄、`>=high` 红。API 租期内显式颜色可覆盖规则；只影响用户显示色灯，不修改传感器报警。

### legacy / dual profile

旧 OP `11`/`12`/`13` 保持一份 scalar 缓存和原字节布局。旧 `12` 选择 legacy profile，新 `16` 选择 dual；只写缓存和所有查询都不能抢占 profile。dual profile 下旧 `13` 的 D1 仍报告 legacy 保存的选择，D2 为 0；查询当前双路必须用新 `17`。旧 CO₂ configure 仍属于 legacy。

Wi-Fi 的新 `display_source.set` 成功后持久选择 dual；旧 `co2_source.set` / `co2_display.set` 成功后持久选择 legacy，同时保留双路配置。profile 与相关配置在同一存储事务中提交；失败不切换。只运行当前 profile 的显示调度，不能由两个周期任务交替争抢。

## 兼容的 scalar schema 1

均使用 [扩展请求](m1-uart.md)。OP 为十六进制。

| OP | 参数 | 作用 |
| --- | --- | --- |
| `11` 写入 Wi-Fi 数值 | A0–1 数字 0..999；A2 格式；A3 灯色；A4 TTL 秒；A5 位置；A6=0 | 完整校验后替换缓存，不自动切换来源 |
| `12` 选择来源 | A0=0 原传感器 / 1 Wi-Fi；A1–6=0 | 只选择两个来源之一 |
| `13` 查询状态 | A0–6=0 | 返回选择、有效显示、缓存及剩余租期 |

格式 A2：bit0..1 为小数点，0=无、1=左位之后、2=中位之后，3 非法；bit2 为保留该位置的原气体名/单位段，0=隐藏、1=显示；bit3..7 为零。灯色 A3：0=关闭、1=红、2=绿、3=黄。TTL A4：0=立即失效、1..60=有效秒数。位置 A5：0=甲醛位、1=PM 位。

单位接口只操作玻璃上实际存在的原气体/单位段。玻璃没有 CO₂ 或 ppm 标识；CO₂ 模式隐藏原气体和单位，不虚构 CO₂ 图标。

OP `13` 结果：D0=schema 1；D1=所选来源；D2=所选为 Wi-Fi 且缓存有效；D3=位置；D4–5=数字；D6=格式；D7=灯色；D8=剩余 TTL 秒，向上取整；D9–13=0。D2 不是显示器硬件回读，也不代表专家屏幕覆盖下的最终可见内容。

TTL 到期恢复直读，即使所选来源仍为 Wi-Fi。新数据续租后可恢复 Wi-Fi 显示；无效数据不能发送伪零。专家屏幕覆盖优先；普通 OTA / 复位过程仍遵循原互斥规则。通用显示配置与租期只存在 RAM，联网模块负责重启后的同步。

以 1234 ppm、甲醛位、黄色、有效 20 秒为例，Wi-Fi 换算为数字 123、左位后小数点，发送二进制：

```text
23 70 11 01 00 7b 01 03 14 00 00 21
23 70 12 02 01 00 00 00 00 00 00 21
23 70 13 03 00 00 00 00 00 00 00 21
```

联网模块当前 CO₂ 显示策略：1..999 为整数；1000..9999 取 `ppm/10`、显示 `1.00`..`9.99`；10000..65535 取 `ppm/100`、显示 `10.0`..`65.5`，除法截断。灯色为 `<低阈值` 绿、`>=低阈值且<高阈值` 黄、`>=高阈值` 红。交替周期和双击覆盖由 Wi-Fi MCU 计算，传感器 MCU 无需知道 CO₂ 含义。

## 按钮事件 schema 1

能力 D9=1 后解析独立的 20 字节事件：

```text
23 71 01 KIND SEQ HELD_HI HELD_LO 00 00 00 00 00 00 00 00 00 00 00 00 21
```

KIND：1=单击、2=双击、3=约 3 秒长按、4=10 秒长按。SEQ 每次事件递增、按 8 位回绕，仅用于相邻重复过滤；不能把零当作无效。HELD 为大端毫秒，最长 65535；单击当前发 0，双击为第二次按住时长。

当前消抖 20 ms，短按为 60..2999 ms。首次短按释放后等待超过 350 ms 发单击；窗口内完成第二次合格短按发双击，双击不再发送原 `0x0f` 切屏事件。单击仍伴随原 `0x0f`。按到 3 秒仅发 KIND=3 和旧 `0x04` 通知；松手时达到 3 秒且不足 10 秒才请求重新配网。连续按满 10 秒发 KIND=4 并直接请求恢复出厂，无需松手。新按键流程不自动发送旧重配网 `0x18` 或显示测试 `0x10`；后者仍可由显式调试命令调用。OTA 和复位等待清除待决点击。

Wi-Fi MCU 处理双击的优先级：

1. 闹钟正在响铃，取消本次闹钟，不执行显示切换。
2. 未响铃且已配置 `switch_display`、当前 profile 和 MCU 能力允许时，dual profile 整体切换两路原始 / 用户来源；legacy profile 保持既有 CO₂ 切换。
3. 其余情况不执行自定义切换。数据过期由租期恢复直读；OTA、复位或配置占用时不接受自定义动作。

## 按键重置事务 m1-reset-v1

`m1-reset-v1` 使用独立命令 `0x72`，不是 `0x70` 的子操作，也不复用 OTA 的 `0x16`。传感器 MCU 请求为 20 字节，Wi-Fi MCU ACK 为 12 字节：

```text
23 72 01 KIND SEQ 00 00 00 00 00 00 00 00 00 00 00 00 00 00 21
23 72 01 KIND SEQ 00 00 00 00 00 00 21
```

这里 KIND=1 重新配网、2 恢复出厂，与 `0x71` 按钮事件的 KIND 分开解释。保留字节必须为零。每个新事务递增 8 位 SEQ、允许回绕至零；同事务每 500 ms 重发相同 KIND/SEQ，最多等待 5 秒。OTA、待决重置或已提交重置期间不得另起按键事务。

Wi-Fi 完整校验请求后调用 `m1_reset(kind == 2)`，仅持久化成功才发送相同 KIND/SEQ 的 ACK。忙或保存失败不 ACK、不记为已提交，允许后续重试。同一已提交事务只重发 ACK、不重复写 Flash；冲突事务忽略，不能升级为恢复出厂。

传感器 MCU 只在本地待决事务的 5 秒窗口内接受 schema、KIND、SEQ 和保留字节全部匹配的 ACK；到达 5000 ms 即失效。孤立、迟到或错误 ACK 不触发复位。确认后拉低 Wi-Fi EN 至少 1 秒，再复位自身，启动时重新拉高 Wi-Fi EN。无有效 ACK 不切 Wi-Fi 电源；超时后松手可重新长按发起新事务。

必须配套升级两颗 MCU：旧 Wi-Fi 忽略 `0x72`，新传感器 MCU 不回退到 `0x18`，也不把恢复出厂降为重新配网。新 Wi-Fi 仍接收旧传感器 MCU 的 `0x18`，按原部分重置保存成功后发送旧固定 `0x16` magic ACK。已有 OTA `0x16` 提交后等待 4 秒、拉低 Wi-Fi EN 至少 1 秒的流程保持不变。

恢复出厂范围沿用 Wi-Fi `m1_reset(true)`：全部 `app_storage` 恢复默认，传感器 MCU 重启清除 RAM 状态；独立 Flash 中的 RTTTL 音乐保留。机器定义与正反样例见 [重置合同](contracts/m1-reset-v1.json) 和[事务向量](contracts/vectors/m1-reset-v1.json)。
