# 接口演进与跨仓库协作

[English](https://phicomm-io.github.io/iotcloud-community-protocols/en/conventions/)

跨仓库功能先在本仓库确定接口与失败行为；实现 PR 引用同一个规范提交，避免 MCU、固件、前端和平台各自解释字段。

## 版本和能力

- 规范版本、HTTP 路径版本、MQTT 协议版本、JSON schema、持久化配置版本、固件版本分别维护。
- 新功能通过 `capabilities`、动作列表和 MCU 扩展能力协商。未知字段可按响应扩展规则忽略；未知动作不能按成功处理。
- 不复用旧字段、主题或操作码表达新含义。破坏性变更使用新 schema / 路径，并提供迁移或明确拒绝。
- 配置写入校验完整请求，拒绝未知字段、错误类型、嵌入 NUL 和越界值。JSON 的字符串、数字和布尔值不能互相代替。
- 原厂版本保留原始字符串。M1 原厂 `11.x`、`17.x` 与开源 MCU 版本属于不同系列，不做语义版本排序。

## 数据和失败行为

时间戳需说明是 UTC、开机毫秒还是样本年龄。跨设备传感器使用 `age_ms` 和本地接收后的经过时间判断新鲜度，不比较两台设备的开机时间。毫秒计数按无符号差值处理回绕；合法有效期须小于半个计数周期。

无效、过期或离线数据不能替换为零。状态使用有效标记并省略不可用值，显示覆盖到期后恢复原始采集。`accepted` 只表示请求被接受；配置持久化、物理输出和重启完成分别验证。

MQTT 重试复用原 `request_id` 和内容；用新编号发送可能再次执行。UART `0x70` 的 `SEQ` 只匹配应答，不保证去重；重发可能重新开始租期或音乐操作，调用方按操作语义处理。

## 配置兼容

读取旧版本后，在 RAM 完成整个迁移和校验，一次提交新配置；写入失败保留原 Flash 并进入恢复配网。保留 Wi-Fi、MQTT、名称与产品设置。不能识别的未来配置不静默覆盖，清空必须由用户明确确认。

恢复备份必须匹配机型、变体、schema、配置版本与长度。完整备份包含密钥，只允许有密码的局域网 HTTP，不经 MQTT 或跨页面消息传递。M1 MCU 音乐单独备份。

## 交付和引用

各实现仓库以 `protocols.lock.json` 固定本仓库的完整提交和 `contracts/registry.json` 的 SHA-256。前端发布仍使用独立的 `frontend.lock.json` 固定不可变制品；协议锁不能替代前端制品锁。

提交协议变更时同步正文、Schema、正反样例和实现关联。自动检查覆盖格式、边界和示例；涉及显示段、按键、恢复和资源预算的变更还需对应的硬件验证。工作分支、文档发布和固件正式发布各自独立。

协议锁的 contracts 列表说明实际角色和消费分支，不能将归档合同当成同时满足的生产声明。例如MCU新producer完整能力应答D13=2，使用m1-uart-v3替换强制D13=0的v2；仍可保留兼容的display-v1/buttons/alarm合同。Wi-Fi consumer确实按D13=0/2协商旧/新分支时，可以同时列v2/v3；前端保留旧消费合同也不意味着它生产UART应答。实现PR应说明各ID对应的角色/分支。

格式 MCU producer 使用 `m1-uart-v4`：保留 v3 全部操作和 D13=2，并增补十进制24/25/26，不能宣称符合旧固定零 v2 producer 合同。Wi-Fi consumer 保留实际协商的各分支，并增加 `m1-display-v3`，以能力和只读 schema3 探测保护新写入。新增严格 HTTP 动作避免重定义冻结 v2 请求；直接 API 数字/标志/灯与本地/MQTT 物理值转换分别约定输入语义。增量发布 schema/向量后同步消费者提交和索引 pin，以旧文件摘要防止既有定义被改写。
